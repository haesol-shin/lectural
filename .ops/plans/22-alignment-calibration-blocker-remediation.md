# Issue #22 alignment calibration blocker remediation

## Scope

**Understood as:** resolve the current calibration blocker without changing fixture truth to whatever the latest threshold vector happens to report, preserve the canonical production gate order, complete an independent calibration corpus, freeze one reproducible threshold artifact, and wire alignment into production only after every freeze gate passes.

This plan amends the failure-family, calibration, and branch-eligibility portions of `22-visual-evidence-efficiency-alignment-amendment.md`. The deterministic ORB/RANSAC worker, fail-closed behavior, and no-production-wire-before-freeze decisions remain unchanged. The earlier “alignment only after direct failure” rule is reopened only because the measured incremental negative is already merged by the direct gate; the frozen end-to-end branch formula must protect that case without weakening pan/zoom recovery.

## Finding and decision

The two reported mismatches have different meanings. `dev_true_transition` has 55 ratio matches while the provisional development vector requires 402, so `ratio_matches` is a valid earlier rejection than `geometry`. `dev_incremental_build` has strong geometry and bidirectional SSIM around `.974`, but the provisional vector sets `scale_min=1.0` and rejects its estimated scale `.9999518` at `matrix`; this is an unstable boundary produced by an intentionally incomplete development corpus, not evidence that the image's semantic label is wrong. The same incremental pair is already accepted by the upstream direct gate with histogram `.9999965` and SSIM `.9841285`, so the currently planned “alignment only after direct failure” branch would never get an opportunity to protect it in production.

Do not rename those expectations to `ratio_matches` and `matrix`, do not weaken or reorder production gates to force `geometry` or `ssim`, and do not alter either image to manufacture the originally predicted path. A semantic negative's ground truth is `different`; its first failed gate is a threshold-dependent diagnostic outcome, not independently authored truth.

Keep `dev_true_transition` and `dev_incremental_build` as classification fixtures with their existing `different` labels and transform classes. Remove the requirement that every semantic negative declare `expected_first_failure_family`. Continue recording `calibrated_first_failed_gate` for observability, but do not make an exact-family mismatch a freeze blocker for ordinary development or held-out rows.

Add branch eligibility to the corpus contract. Every scored row must record the pHash persistence outcome, direct histogram/SSIM outcome, whether production invoked geometric alignment, and the final expected pipeline label. Alignment-only confusion matrices may characterize the classifier, but freeze requires a separate end-to-end confusion matrix using the exact production state machine and evaluator below. A negative that is merged before transform-aware evaluation is a false positive even if an offline alignment call would reject it.

The content-change veto is required, not optional, because the measured incremental negative already passes the direct gate and the current alignment metrics alone cannot establish preservation of added content. Every persistent candidate therefore enters the same transform-aware evaluator even when direct histogram/SSIM says `same`. This is the exact production formula: first evaluate identity content change when `direct_same=true`; return `same` immediately if that identity veto passes; invoke alignment plus aligned content change when `direct_same=false` or when `direct_same=true` but the identity veto fails; return `same` only if every alignment gate and aligned content-change predicate passes; otherwise return `not_same`. Thus `duplicate = identity_same or aligned_same`, where `identity_same = direct_same and identity_content_change_passes` and `aligned_same = alignment_was_required and every_alignment_gate_passes and aligned_content_change_passes`. A timeout, worker crash, decode failure, incomplete metadata, unavailable alignment, or exception on a required fallback produces `not_same`; production keeps the candidate as distinct. The worker skips ORB/RANSAC only after a passing identity path and may not skip identity content change. Calibration and production call the same `evaluate_visual_candidate` function with the same metadata schema, thresholds, gate order, fallback condition, and result enum; no calibration-only branch formula is allowed.

The content-change calculation is deterministic. Convert the compared BGR images to `COLOR_BGR2GRAY`; on the direct path apply the existing direct-pair size normalization first by resizing the candidate to reference width/height with `INTER_LINEAR`, then compare in reference coordinates with an all-valid identity support mask; on the aligned path use the already defined forward and reverse warps and eroded support masks. For each direction calculate `absdiff` in uint8-promoted integer arithmetic, mark a pixel changed when `absdiff >= pixel_delta`, remove no components and apply no additional morphology, then use `connectedComponentsWithStats(..., connectivity=8)` on the valid-mask-intersected binary map. `changed_fraction` is changed valid pixels divided by all valid pixels; `largest_changed_component_fraction` is the largest non-background component area divided by all valid pixels, or zero when no component exists. Aggregate each metric as the maximum of forward and reverse values; the direct identity path records two identical directional values. `content_change` passes only when both maxima are `<=` their frozen maximum thresholds. Empty support, non-finite values, missing directions, OpenCV error, or any unavailable input fails `content_change` and returns `not_same`.

Threshold search uses two explicit development subsets derived from confirmed sequence events. The `alignment_fit` subset contains only events for which the production direct gate returns `direct_same=false`; only this subset supplies candidate values for ratio-match, matrix, inlier, residual, geometry, coverage, SSIM, and scale fields. Direct-true identity-veto-failure fallback events must pass final development/held-out evaluation but do not contribute alignment threshold candidates. The `content_fit` subset contains every confirmed event, including direct-true identity passes, direct-true alignment fallbacks, and direct-false alignment events; only this subset supplies content-change observations and candidate values. Pair rows are event-measurement cache entries only: each cache row must name one canonical `event_id = sequence_id + confirmation_frame_index + candidate_start_index`, may be reused to avoid recomputation, and contributes no independent sample or weight. Each confirmed sequence event enters its applicable fitting subset and final confusion matrix exactly once even if the same path pair appears in the cache or in another diagnostic table.

Content search uses the fixed pixel-delta domain `[8, 12, 16, 24, 32, 48, 64]`. For each delta, derive finite development-only candidate domains for `changed_fraction_max` and `largest_changed_component_fraction_max` from all `content_fit` events, subject to accepting every development positive. Extend the serialized threshold order by appending `pixel_delta`, `changed_fraction_max`, and `largest_changed_component_fraction_max` after `scale_max`. Build alignment candidate domains only from `alignment_fit`, build content candidate domains only from `content_fit`, and retain only combined vectors for which every development event is classified correctly by the actual production `evaluate_visual_candidate` path. Tie priority is smaller `pixel_delta`, then smaller `changed_fraction_max`, then smaller `largest_changed_component_fraction_max`, after the existing fields' priority. Serialize the integer delta as a base-10 integer and fractions as IEEE-754 hexadecimal values.

The 14-field search is exact branch-and-bound, not an approximate grid. Enumerate the seven pixel deltas outermost; within each delta traverse the remaining fields depth-first in serialized tie-priority order. Candidate domains contain sorted unique finite development observations filtered to positive-safe values, with fixed scale bounds represented as singleton domains. At each prefix, fill every unassigned monotone field with its strictest positive-safe value and evaluate all development events through `evaluate_visual_candidate`; if this completion cannot reject every remaining negative, prune the prefix because every weaker completion also fails, while a prefix that already rejects a positive is pruned immediately. Memoize canonical `(pixel_delta, prefix, surviving_event_ids)` states, stop at the first valid leaf in tie-priority order, and record visited leaves, pruned prefixes, domain sizes, and memo hits. Hard limits are 1,000,000 evaluated prefix/leaf states, 120 seconds wall time, and 512 MiB additional peak RSS for the search process; reaching any limit returns no vector, records `search_cap_exceeded`, and forces `frozen:false` rather than falling back to a heuristic. A test-only exhaustive Cartesian oracle runs on bounded synthetic domains containing direct, fallback, and alignment events and must return the identical selected 14-field vector or identical no-vector result; the optimized search may ship only while this equivalence test passes.

Freeze requires both fitting subsets to be independently viable. `alignment_fit` must contain at least one `same` and one `different` event and every manifest-declared direct-false alignment class, including both pan/zoom directions and the alignment-relevant transition, shared-template, panned incremental, coverage, geometry, residual, descriptor, and scale negatives. `content_fit` must contain at least one `same` and one `different` event, both `direct_same` values, and every manifest-declared content class, including direct static duplicates, direct incremental builds, aligned pan/zoom positives, panned incremental builds, and shared-template content changes. Development and held-out corpora must also include a mandatory `direct_true_identity_veto_fail_alignment_same` positive in both pan and zoom directions, plus a `direct_true_identity_veto_fail_alignment_different` incremental/shared-template negative, proving that fallback recovers coordinate-change false negatives without allowing changed content through. Under the selected vector, each mandatory fallback event must trace `direct_same=true`, identity `content_change` failure, and alignment invocation; the positive must then return aligned `same`, while the negative must return `not_same`. A vector that bypasses these traces by making the identity threshold permissive is invalid. Missing label polarity, direct-path polarity, fallback polarity, required trace, or required transform-class coverage in either development fitting subset produces `frozen:false` before threshold search; held-out must independently cover the same production paths and required class sets for final confusion evaluation.

## Production sequence contract

Replace pair-only end-to-end claims with sequence fixtures. Each sequence has a `sequence_id` and ordered frames containing `path`, monotonic `timestamp`, independently authored `expected_visual_id`, and optional source transform metadata. Pair rows remain inputs to threshold fitting, but only sequence execution can satisfy the production branch gate.

Extract a pure `advance_dedupe_state` helper from `dedupe_frames` and call it from both production and calibration sequence replay. Its state is `{kept_index, kept_hash, previous_hash, candidate_start_index, candidate_hash, candidate_count}`. For each ordered frame it records the Hamming distance from previous and kept hashes and applies these transitions exactly: a hash near `kept_hash` resets candidate state and emits `phash_duplicate`; otherwise a missing or hash-different pending candidate sets `candidate_start_index=current_index`, `candidate_hash=current_hash`, and `candidate_count=1`; a hash near the pending candidate increments `candidate_count`; counts below `PHASH_CHANGE_PERSISTENCE` emit `phash_change_pending`; reaching persistence compares the kept frame with the frame at `candidate_start_index` through `evaluate_visual_candidate`; `same` leaves the kept reference unchanged, `not_same` or any unavailable/failure outcome appends the candidate-start frame and makes it the new kept reference; either terminal decision resets candidate state. The confirming sample is recorded in the trace but is not silently rescored as a new candidate, matching production behavior.

The sequence trace records before/after state, frame index/timestamp, kept reference, candidate start, counter, pHash distances, direct metrics/result, evaluator invocation and path (`identity_content_change` or `alignment_content_change`), evaluator result, first failed gate, and kept output indices. A scored event exists only when persistence reaches its confirmation count. Its expected label is `same` when the candidate-start frame's `expected_visual_id` equals the current kept frame's `expected_visual_id`, otherwise `different`; its predicted label is `same` only when the shared evaluator returns `same`. Development and held-out end-to-end confusion matrices are computed from all scored events through their actual production paths, while pending/reset events are verified against expected state traces but excluded from the confusion denominator. A development vector or held-out run passes only when this all-event confusion matrix has zero false positives and zero false negatives.

Test gate semantics separately from calibration accuracy. Table-driven unit tests shall feed controlled metadata into the shared `evaluate_visual_candidate`: `direct_same=false` cases isolate `opencv`, `decode`, `descriptor`, `ratio_matches`, `affine`, `matrix`, `inliers`, `residual`, `geometry`, `coverage`, `ssim`, and aligned `content_change` in canonical order, while `direct_same=true` cases prove that alignment prerequisites are skipped and identity `content_change` is still mandatory. Each case must satisfy every earlier predicate on its actual path and fail exactly the target predicate. Image fixtures may assert an exact failure family only when explicitly marked as a gate-contract probe and excluded from threshold search and confusion matrices; no such assertion is required merely because a row belongs to a semantic transform class.

## Corpus correction

Create a deterministic alignment fixture generator dedicated to this manifest instead of reusing incidental benchmark slides as the complete calibration set. Generator recipes establish labels before ORB/RANSAC runs: a positive is the same authored canvas transformed within the supported pan/zoom envelope, and a negative changes authored semantic content or deliberately violates a named model assumption. Commit the generator version, seed, source-content ID, output paths, SHA-256 values, label, transform parameters, and transform class for every row.

Populate every required transform class with at least two independent development seeds and one independently authored held-out seed. Pan/zoom positives must cover both directions and bracket the observed local scales `.9379` and `1.1508`; use the predeclared supported scale envelope `[0.80, 1.25]` in development generation so scale bounds express the supported product behavior rather than rounding noise around `1.0`. Negative coverage must include incremental builds, panned/zoomed incremental builds, shared-template different content, same-palette different layout, too few descriptors, affine failure, outlier-heavy matches, high residual, out-of-envelope scale, concentrated/collinear inliers, one-way coverage loss, low masked SSIM, and true transitions.

The currently inspected `holdout_near_duplicate` and `holdout_true_transition` rows are no longer valid final holdout evidence because their measurements influenced this remediation. Move them to development or a non-scored regression split. Generate replacement held-out rows from new content IDs and seeds after the generator and threshold-search rules are fixed; do not inspect or use their metrics during threshold selection. The first time any held-out event is observed, that entire held-out manifest version is consumed. If it fails, retire the whole split, promote any useful failing cases to development, diagnose the general cause, and generate an entirely new held-out split from new content IDs and seeds; unchanged passing rows from the retired split may not be reused as final evidence. The final report preserves a `retired_holdouts` history containing each retired manifest SHA-256, canonical result-payload SHA-256, class/path coverage, confusion matrix, failure event IDs and reasons, retirement timestamp, and successor manifest SHA-256; retired metrics are never included in final held-out scores or threshold domains.

## Calibration contract changes

1. Update manifest validation so pair rows require `expected_label` and `transform_class`, sequence rows require `sequence_id` and ordered timestamped frames with `expected_visual_id`, and `expected_first_failure_family` is absent or diagnostic-only. Add a separate optional `gate_contract_probes` collection if image-level exact-family probes are retained; exclude it from threshold candidate generation, confusion matrices, and class-completeness counts.
2. Delete `negative_failure_mismatches` from the freeze predicate for scored semantic rows. Optional image-level probes may produce `gate_contract_failures` in the report; the table-driven canonical evaluator tests remain an external test-suite gate and are not fabricated as calibration output.
3. Replace the narrower public decision entry point with `evaluate_visual_candidate`, the single evaluator used by measurement, pair calibration, sequence calibration, report generation, and production. It owns direct-path selection, alignment gate evaluation, content-change evaluation, and terminal result mapping. Keep lower-level metric extraction private and remove duplicate ad hoc decision derivation. Add `content_change` after `ssim` in the aligned gate order and after direct confirmation in the identity path.
4. Run threshold selection only on confirmed development sequence events with the exact `alignment_fit` and `content_fit` partition above. Keep the fixed field ordering and combined exhaustive-oracle equivalence test. Treat the supported scale envelope `[0.80, 1.25]` as fixed policy bounds recorded in the artifact, not extrema learned from observed development values; the out-of-scale class validates those bounds. Alignment threshold domains come only from alignment-path development events, content-change domains come from all development events, and final vector acceptance uses the all-event production confusion matrix.
5. Apply finite-prerequisite checks by actual production path. A `direct_same=true` positive requires valid decode, direct metrics, identity support, and both content-change metrics but does not require descriptors, ratio matches, affine, matrix, inliers, residuals, geometry, aligned coverage, or aligned SSIM to exist. A `direct_same=false` positive requires every alignment and aligned-content prerequisite. Every development/held-out scored event must have a terminal canonical decision; `unavailable` is a calibration failure, never a negative classification success.
6. Record per-event fitting-subset membership, production path, expected label, actual result, actual first failed gate, raw measurements, split, generator provenance, and file hashes. Preserve actual first-failure distributions as diagnostics so an unexpectedly dominant early gate can be reviewed without being confused with ground truth. Build a canonical report payload using UTF-8 JSON with sorted keys, compact separators, relative normalized paths, IEEE-754 hexadecimal floats, and no wall-clock timestamps, absolute paths, process IDs, elapsed times, or RSS samples; operational telemetry remains outside this payload. The payload includes manifest and fixture hashes, provider/build signature, evaluator/search protocol versions, serialized 14-field threshold vector, ordered per-event results and first failed gates, confusion matrices, sequence traces, coverage checks, search counters, blockers, and retired-holdout hashes.

7. Reproducibility reruns the complete measurement, threshold fitting, sequence replay, and canonical payload construction ten times through one worker session and twice through fresh workers. A pass requires all twelve runs to have byte-identical serialized threshold vectors, identical ordered `(event_id, result, first_failed_gate)` sequences, and the same canonical report-payload SHA-256; matching raw integer counts alone is insufficient. Any mismatch records all hashes and forces `frozen:false`.

## Acceptance gates

- No fixture expected label or authored content is changed solely to match a measured first failure.
- Every canonical failure gate has an isolated evaluator test; semantic corpus rows are judged by `same` versus `different` only.
- Every scored sequence event has an end-to-end decision from the production state helper and shared evaluator, and no negative is counted as protected by a gate production would never invoke.
- Direct-true identity-veto failures exercise the exact alignment fallback in both label directions and both final splits; unavailable fallback preserves the candidate as distinct.
- Development and final held-out content IDs/seeds are disjoint, and no observed held-out row is reused as final evidence.
- The exact search finishes below its state/time/RSS caps and matches the exhaustive oracle; cap exhaustion is never treated as calibration success.
- The canonical artifact is `frozen:true`, provider-pinned, complete, zero-error on development and a fresh held-out split, and reproducible by identical threshold vectors, ordered event decisions, and canonical payload hashes across all 10+2 runs.
- Production constants exactly match the artifact and production calls the same evaluator used by calibration.
- The local YouTube pan/zoom case passes without merging the adjacent true transition, and the full offline suite, doctor, diff check, and resource benchmark pass.

## Open judgment

The only deliberate judgment left for implementation review is whether to retain any image-level `gate_contract_probes`; the minimum safe design is the isolated metadata unit-test matrix. This choice must not affect threshold fitting, sequence confusion matrices, or held-out independence. The content-change veto, production formula, sequence state transitions, unavailable behavior, and threshold-search order are not optional judgments.
