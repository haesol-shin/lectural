# LecturAL evidence quality and resource benchmark — v1

Dev/maintainer-only benchmark for Issue #21. This is **not** part of the public `lectural` CLI/JSON contract and does **not** affect the Issue #19 completeness gate (pass/warn/fail semantics are unchanged and unaffected). It answers a different question: is LecturAL's speech/OCR evidence trustworthy, and at what CPU/RAM/storage/time cost, on the current stack.

## Fixtures

Committed under `tests/fixtures/benchmark/`, generated by `tests/fixtures/benchmark/generate.py` at a locked seed (`--seed 42`, default). Three language fixture sets, each with a `_unusable` companion directory for the caption-fallback case:

| Fixture ID | Language | Content |
|---|---|---|
| `en_terms_01` | English | Proper noun ("Geoffrey Hinton"), year ("1986"), technical terms ("backpropagation", "multi-layer perceptrons"), numbers ("0.05", "128") |
| `ko_terms_01` | Korean | Proper noun ("에츠허르 데이크스트라" / Edsger Dijkstra), year ("1956"), technical terms ("최단 경로 알고리즘", "우선순위 큐"), number ("256") |
| `mixed_terms_01` | Korean/English mixed | Framework/researcher names ("PyTorch", "Yann LeCun"), technical terms ("Convolutional Neural Network", "AdamW"), numbers ("64", "0.01") |

Each fixture set contains:

- `script.txt` / `gt.json["script"]` — the ground-truth script, authored
  **before** synthesis. This is necessary but not sufficient ground truth on
its own (see "Independent review" below).
- `audio.wav` — synthesized via `pyttsx3` (SAPI5: Microsoft Zira for
English, Microsoft Heami for Korean/mixed). Real synthesized speech, not a placeholder tone.
- `audio_degraded.wav` — background noise / silence gaps injected via
`ffmpeg` (documented fallback: `audiomentations` was not installed in the generating sandbox; if available in a future regeneration, prefer it for RIR-based augmentation).
- `video.mp4` / `video_360p.mp4` — slide deck rendered as PNG frames
(`slides/*.png`, via PIL) assembled into video with `ffmpeg`; `video_360p` is a lower-bitrate re-encode for the resolution-effect factorial.
- `slides/slide_02_near_dup.png` — a deliberate near-duplicate of
`slide_01_concept.png` (tiny pixel shift), and `slide_03_inc_base.png` / `slide_04_inc_ext.png` — a deliberate incremental build-up pair (same slide, strictly more text), so `visual.dedupe_frames`'s duplicate-rate and persistence/incremental logic have real positives to score.
- `slide_degraded_l1.png` / `slide_degraded_l2.png` — two visual-degradation
severity levels (documented fallback: PIL Gaussian blur + contrast/ brightness jitter; `augraphy` was not installed in the generating sandbox).
- `captions_usable.vtt` / `captions_unusable.vtt` — a caption file that
passes `lectural.acquisition.captions_are_usable`'s heuristic and one that deliberately fails it (sparse/malformed), for the caption/fallback matrix.
- `gt.json` (and an identical `ground_truth.json`, both written from the
same in-memory source at generation time, not independently maintained): ground-truth JSON — see schema below.

### Ground truth JSON schema

```json
{
  "fixture_id": "en_terms_01",
  "language": "en",
  "script": "full script text — the WER/CER ground truth",
  "speech_spans": [[1.0, 4.089], [5.089, 12.052]],
  "slide_change_timestamps": [0.0, 5.0, 13.0, 18.0],
  "key_fields": {"lecture_title": "Lecture 4: Optimization", "key_author": "Geoffrey Hinton"},
  "terms": ["Geoffrey Hinton", "1986", "backpropagation", "0.05", "128", "Multi-layer perceptrons"],
  "usable_ocr_threshold_chars": 8,
  "degradation": {"visual": ["blur_l1", "near_duplicate"], "audio": ["noise_l1", "silence_gap"]},
  "caption_variant": "usable",
  "slides_text": {"slide_00_title": "...", "slide_04_inc_ext": "..."},
  "near_duplicate_timestamps": [9.0],
  "incremental_timestamps": [18.0],
  "independent_review": {"reviewer": "generator_synthesis_notes", "date": "YYYY-MM-DD", "notes": "..."}
}
```

`terms` is the ground truth for `terminology_recall` — the actual spoken/ written technical terms, proper nouns, and numbers. It must **not** be confused with `key_fields`' schema *key names* (`"key_author"`), which are never spoken and would silently zero out recall if used by mistake (this was caught and fixed during implementation review — see git history on `scripts/benchmark.py`'s `evaluate_quality_metrics`).

### Independent review

Per fixture set, one independent review pass compared the **rendered audio/video** (not just the script) against the script once, recorded in `gt.json["independent_review"]` and in `tests/fixtures/benchmark/REVIEW.md`. This is what makes the fixture "independently reviewed" ground truth rather than a tautological self-check of the generator: it is the one place a human (or a separate fresh-context reviewer) confirms the TTS actually pronounced the technical terms correctly and the slides rendered legibly, rather than trusting the generator's own claim.

## Metrics (`lectural_bench/metrics.py`)

| Function | Metric | Notes |
|---|---|---|
| `wer_cer` | WER / CER | `jiwer` + `whisper_normalizer` when installed (English); pure-Python fallback (space-insensitive Hangul-syllable edit distance) otherwise. Never requires a runtime dependency to be testable. |
| `terminology_recall` | Terminology recall | Case-insensitive, normalized substring match of `gt["terms"]` against the hypothesis text. |
| `timestamp_error` | Cue-timestamp median/P95 | **Cue-level only.** Word-level P95 is out of reach because `lectural/speech.py` sets `word_timestamps=False`; this benchmark does not change that. |
| `voiced_recall_and_gap` | Voiced-speech recall / max untranscribed gap | Scored against the fixture's authored `speech_spans`, never against `lectural.vad`'s own output on the same audio (that would be circular). |
| `frame_recall_and_duplicate_rate` | Frame recall / duplicate rate / near-dup dropped / incremental retained | Scores `visual.extract_candidate_frames` + `visual.dedupe_frames`'s **output** against `slide_change_timestamps`, near-duplicate timestamps, and incremental build timestamps; production dedupe logic itself is never modified or reimplemented. |
| `ocr_quality` | OCR CER / key-field recall (exact + fuzzy) / usable | `Levenshtein` when installed; `difflib.SequenceMatcher` fallback otherwise. CER is computed against authored slide reference text (`slides_text`); `key_fields` is dedicated to exact and fuzzy key-field recall. Exercised against the visually-degraded slide variants. |

Normalization rules: English text is lowercased, punctuation-stripped, and whitespace-collapsed via `whisper_normalizer` when available. Korean text is normalized by stripping punctuation/whitespace while preserving Hangul syllables, digits (e.g. 1956, 256), and ASCII letters, and computing CER space-insensitively (Korean word segmentation is not meaningful for a character-error-rate comparison the way it is for English WER).

## Execution matrix

`scripts/benchmark.py` exercises, per fixture:

```
{caption (mocked fetch), caption-fallback (unusable / fetch-failure), forced-STT}
  × {OCR-on, OCR-off (--skip-ocr)}
  × {EN, KO, mixed}
  × {cold, warm}
  × {clean, degraded (`--media-variant`)}
  × 3 repetitions (median + variance)
```

`--media-variant clean` (default) uses the fixture's clean TTS audio and 720p video. `--media-variant degraded` uses `audio_degraded.wav` (noise/silence-injected) and `video_360p.mp4` instead, falling back to the clean asset when a degraded one is absent for a given fixture — this is what actually exercises the injected failure modes end to end, rather than leaving `audio_degraded.wav`/`video_360p.mp4` as committed but unused sidecars. Independent of this flag, every run also scores OCR against the fixture's standalone visually-degraded slide images (`slide_degraded_l1.png`, `slide_degraded_l2.png`) under `quality_metrics.degraded_slide_ocr`, since the assembled video itself is always built from clean slides.

Frame selection (`extract_candidate_frames` + `dedupe_frames`) always runs when the fixture has video — it is not a separate axis. OCR preprocessing-effect attribution (raw vs. `ocr.ocr_image`'s built-in ROI+upscale+Otsu preprocessing) is **explicitly out of reach** for this harness: production `ocr_image` always preprocesses and `lectural/ocr.py` is never modified by this benchmark, so the issue's "preprocessing ... where measurable" acceptance criterion is knowingly scoped to the resolution (360p vs. 720p source) and STT model-size (`small` vs. `medium`) factorials instead of silently dropped.

### Caption/fallback injection mechanism

Local synthetic fixtures cannot reach `lectural.acquisition.acquire_speech`'s real caption/fallback branches on their own — those only trigger for a `SourceKind.YOUTUBE` source, and local sources always transcribe. The harness builds a `YOUTUBE`-shaped fixture source and monkeypatches `acquisition.fetch_caption_segments` (to return the fixture's parsed VTT cues, return an unusable/near-empty list, or raise) and `media.resolve_audio` (to the fixture's local audio), exercising the real `acquire_speech` dispatch logic without any change to `lectural/acquisition.py` — the same dependency-injection pattern already used by `tests/test_acquisition.py`.

### Observational rows

The live 555-second YouTube run (`docs/reports/observational_555s_perf_smoke_2026-06-14.json`, originally produced by `scripts/perf_smoke.py`) is embedded via `scripts/benchmark.py --observational-perf-smoke <path>` as one `"observational": true` row, separate from `results`. It is **never** repeated 3x, never cold/warm-controlled, and never treated as ground truth or merged into any median/variance aggregate.

## Supported profiles

| Profile | Status |
|---|---|
| x86_64 (Windows/Ubuntu/macOS dev + CI) | Supported; CI (`ci.yml`) already runs the *offline* suite here, not the real heavy benchmark. |
| ARM64 (`pi-server`, Debian 13 trixie, 4 cores) | Verified reachable; `lectural doctor` reports `ready` after `uv pip install -e ".[run]"`, including a working `paddleocr`/`paddlepaddle==2.6.2` import and engine init. Opt-in only; no default profile is set by this benchmark. |

No profile is a product default from this issue — non-goal: "Production optimization or a mandatory 720p minimum."

## Measurement procedure

```bash
# Offline contract/schema checks only (no heavy deps, part of the normal gate)
uv run --with pytest --with numpy pytest tests/test_bench_metrics.py tests/test_benchmark_harness.py tests/test_fixtures_smoke.py -q

# Real benchmark run (opt-in, requires the `bench` extra and lectural's `[run]` extra)
uv run --with pytest python scripts/benchmark.py \
  --fixtures-dir tests/fixtures/benchmark \
  --out output/benchmark \
  --platform-label x86_64 \
  --warm --reps 3 \
  --observational-perf-smoke docs/reports/observational_555s_perf_smoke_2026-06-14.json

# Repeat with --cold and --skip-ocr for the paired comparisons; repeat on
# pi-server with --platform-label arm64-pi-server after syncing that
# checkout to main and re-running `lectural doctor`.
```

Each report row records its exact `config` (fixtures dir, cache mode, reps, `skip_ocr`, model), the host `machine` spec and `dependency_versions`, and every per-repetition raw measurement under `runs`, per the issue's "exact commands, fixture identifiers, environment, raw measurements" acceptance criterion.
